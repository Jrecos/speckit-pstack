# Authoring a skill in this host

The packaged guide the pstack mode routes to. It replaces the editor built-in the
upstream text assumed, and it describes what this project can actually validate.

## What a skill is here

A skill is a directory with a `SKILL.md` whose YAML frontmatter carries `name` and
`description`, plus any references and scripts it needs. Two kinds exist in this
project:

- **Extension resources**: `.specify/extensions/pstack/resources/skills/<name>/`.
  Generated by the importer, never hand-edited. A change belongs in
  `tools/overrides/` or `tools/pstack_transforms.py` and comes back through a
  re-import.
- **Project skills**: a project skill directory this host discovers, the first
  entry of `skills_dirs` from
  `.specify/extensions/pstack/runtime/pstack-native.py paths` unless the user names
  another. Hand-authored and project-owned: the place for verification skills,
  personal modes, and repo conventions. Write the skill into exactly one discovered
  directory. Only when that list is empty does the skill go under
  `.specify/pstack/skills/<name>/`, and then the instruction file or task brief has
  to point at it, because nothing loads it automatically.

## Frontmatter

```yaml
---
name: verify-checkout
description: Drive the checkout flow in a real browser and prove the totals change. Use for checkout regressions, pricing questions, and "does the order still go through".
---
```

- `name` is kebab-case and matches the directory.
- `description` is the whole trigger surface. Name the app, the surface, and the
  situations that should reach for it, in one or two sentences. A vague description
  is a skill that never loads.
- `disable-model-invocation: true` is for skills a human invokes explicitly. It is a
  host hint, not a guarantee; the resource still has to stand on its own text.
- Do not invent other fields. A field the host does not read is decoration that
  drifts.

## Shape of the body

1. Open with the one-line contract: what the skill does and what it needs.
2. Give the exact commands or surfaces to exercise, with the values that matter.
3. State what proves success. Name the observable end state, not the action taken.
4. Add a `Gotchas` section for surprises a cold reader will hit, and nothing else.
5. No phase narration. The assertion or the log string documents the step.

A skill file is read cold, mid-task, by an agent that has never seen this repo.
Write for that reader: absolute-enough paths, no assumed state, no "as discussed".

## Validate before you ship

- Frontmatter parses and `name` matches the directory.
- Every relative link resolves from the file's own directory.
- Every command in the body was actually run once, in this project, on this host.
- If the skill claims a capability (browser, terminal, scheduler, an external
  service), `.specify/extensions/pstack/runtime/pstack-native.py capability-report`
  agrees. A skill that claims a capability the host reports unavailable is broken,
  not aspirational.
- The skill sits in exactly one directory that `.specify/extensions/pstack/runtime/pstack-native.py paths` lists under
  `skills_dirs`, with no second editable copy and no symlink between locations, and
  the host lists it in a fresh session. A skill nothing can load is dead weight; a
  duplicated skill is the copy that goes stale.

## Changing an existing skill

Trivial edits (a bullet, a tightened sentence, a stale fact) the authoring agent
makes directly. A substantive edit (a new section, a pattern table, more than about
ten lines) deserves the draft / test / iterate loop: write the change, exercise the
skill once in the situation its description claims to cover, then keep or revert it
on the evidence. If the skill failed to trigger when it should have, fix the
`description` first, because that is the part the host matches on.

## Where this leaves the upstream dependency

The deslop checklist (`.specify/extensions/pstack/resources/dependencies/deslop.md`)
and the control references (`control-cli.md`, `control-ui.md`) ship beside this file.
They are edited the same way as this one: in the extension tree, through the
importer, with the translation recorded.
